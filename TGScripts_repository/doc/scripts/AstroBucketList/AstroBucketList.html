AstroBucketList

1 Description

[hide]

Astro Bucket List maintains Stellarium observing lists inside PixInsight 1.9.5 or later using the V8 JavaScript runtime. It displays objects in a flat table with their IAU constellation, uses configurable planning months, and records which objects you have imaged. You create your own lists or open and import Stellarium collections.

2 Start and use the script

[hide]

Choose Script > TG Scripts > Astro Bucket List. The script requires PixInsight 1.9.5 or later with the V8 runtime and its standard CatalogStarGenerator and AnnotateImage libraries. The documentation button in the lower-right corner opens this guide.

By default, a normal launch opens an empty list. No predefined bucket list is loaded. Use Add object to enter targets, New list to create additional lists, Open to load a collection, Import list to bring one saved list into a chosen destination, or Merge lists to retain the list structure of imported files. Open offers to save any unsaved changes before replacing the current collection.

Save writes to the current collection file and asks before overwriting it. Declining keeps the existing file and your unsaved edits. The first Save asks for a filename; Save as lets you choose a separate file. Selecting an existing file in Save as or Export uses the file chooser's overwrite confirmation. When a save replaces an existing file, its exact previous contents are kept beside it as filename.sol.bak (for example, MyTargets.sol.bak). Each successful replacement updates this single backup to the immediately preceding version; no timestamped backup copies are created. Save as and Export also keep a .bak file when replacing an existing destination. Saving to a new filename creates no backup. Cancelling or declining an overwrite leaves the collection and its backup unchanged. Saving keeps the collection and backup at stable filenames, including in synchronized folders. It validates the new collection in local temporary storage, copies the exact previous bytes to .bak, then writes and verifies the new contents at the original collection path. Temporary files are not placed beside the collection. A failed write keeps the collection marked as unsaved and attempts to restore the previous files. The error reports a local recovery folder containing the staged new collection and available preceding versions; retain these files if restoration fails. Completed saves remove their local temporary copies. Keep your collection outside the script installation directory. Automatic reopening is off by default. Enable Remember last opened or saved collection in Configuration > Startup to reopen the most recently opened or saved collection on normal launches. If the remembered file is missing or unreadable, startup reports the full path and opens an empty list. Use Open to select the file at its current location; successful Open or Save updates the remembered path. The preference stays enabled, and the old path is retained until a replacement opens or saves successfully.

Select a list from the List menu, or choose All objects to see every target once. The table has one row per object and no collapsible groups. The Constellation column beside Select / object identifies the IAU region for every row, including separate Serpens Caput and Cauda entries. All sorting modes keep the same flat layout. Checkboxes in the first column select objects for Add selected to list, Move selected to list and Export selected; they do not represent imaging status. These three actions use checked objects whenever any are checked, including objects hidden by filters or in other lists. With no checks they use highlighted rows. The buttons are disabled only when neither set contains an object. Use Ctrl-click to highlight individual rows or Shift-click to highlight a range, then choose Check selected to check all highlighted objects for these batch actions. This adds to existing export checks, including hidden checked objects. Highlighting a row alone does not check it. Click the sole highlighted row again to deselect it. This clears the active object, Object information and single-object previews, while retaining export checks, filters and sorting. It does not change imaging status or collection data. When several rows are highlighted, a plain click first reduces the selection to one row; another click deselects that row. Ctrl-click and Shift-click retain their normal multiple-selection behavior. Checkbox clicks keep their separate check/uncheck action. Double-click still selects the object and switches to Finder chart. A deliberately deselected sole result remains deselected when sorting or refreshing the same view; selecting a row or navigating with the keyboard activates an object again. All filtered objects Finder charts remain available because they depend on visible rows rather than the current object. Check selected is disabled when no rows are highlighted. Check shown checks all rows in the current filtered view, retaining all previous export checks. Uncheck all clears every checked object, including those currently hidden. The footer reports highlighted rows as selected separately from checked objects. Edit object, Remove from list, object information and chart previews refer to the current row when several rows are highlighted. Object selections are temporary and are not saved in the collection or process instance. The Object type column beside the name shows the classification supplied by the object catalog, such as Galaxy, Planetary nebula or Open star cluster. Recognized catalog abbreviations are expanded for display. If only a broad classification is available it is shown as Deep-sky object or Star; an entry without a classification is shown as Unspecified. The column uses saved catalog information and does not trigger lookups.

The Comments column shows your saved imaging notes. Leftover hollow-circle symbols and generated bracketed month/constellation headings containing source-line references are removed from comments when a collection is opened or imported, and from comments saved or exported by the manager. Automatic cleanup on opening is treated as the loaded baseline and does not trigger a save prompt. It is included in the next explicit save or export. Other comment text and line breaks are retained. The cleaned comments are used throughout the table, editor, object details and exported lists. Long or multiline remarks have a compact one-line preview; hover over the cell or select the object to read the full text in its tooltip or details pane. Use Edit object > Comments to enter or change this text, then Save the collection. Existing imaging notes appear automatically.

The Filters column shows saved filter information. For an object without an explicit Filters value, recognizable filter mentions in its comments are shown, including combinations such as LRGB, SHO, HaRGB and individual emission-line filters. These are mentions from your notes, not automatically generated exposure recommendations. Edit object > Filters lets you enter any filter names, correct the suggested text or clear it. An explicitly cleared value remains blank. Filter information is saved with the collection and retained by catalog lookups.

The main window has Table, Finder chart and DSS survey image tabs. Select an object in Table to use either preview tab. The Collection group contains the file path and Open, Import list, Merge lists, Save, Save as and Export. The separate Lists group contains a compact, unlabelled list selector with New list, List details and Delete list underneath. Collection and Lists sit side by side, leaving spare space on their right. Hover over the selector to read the full selected list name. Both are inside one collapsible Collection and lists section above all three tabs. It starts expanded; click its header to hide or restore both groups together. Collapsing it gives more room to the table or preview, retaining the active list, selection, filters, sort order, export checks and unsaved edits. The section stays in its chosen state when changing tabs. Collection, Lists, Filter objects and Sort rows remain compact and aligned to the left, with spare window width to their right. The object table and previews use the available window width. The minimum window size follows the space required by the controls, including the no-results notice and the expanded or collapsed Collection and lists and object-information sections, so shrinking the window keeps controls separated.

Above the table, a single collapsible section named Find, filter and sort contains the Find row, the Filter objects group and the Sort rows group. It starts expanded. Click its header to hide or restore all three together without shrinking the window; the table uses the freed height. Collapsing retains search text, filter choices, sorting, highlighted objects, export checks and collection edits. Filter objects and Sort rows retain separate group titles within the shared section. Find occupies its own row with a Clear search button. Clear search removes only the search text and retains filter choices, sorting and export checks. Below it, Filter objects arranges Month, Constellation, Target band, Imaging status and Object type in two labelled columns. These controls determine which objects are shown. Reset filters clears all six filtering controls together and restores every object in the selected list. It retains the selected list, sort order, highlights for currently visible rows and all export checks, including hidden checked objects. It does not change imaging status, target-band classifications or saved optical filter information. The button is disabled when no filter is active. The separate Sort rows panel changes only the order of those matching rows, using Sort by. It does not hide objects or clear filters.

Sort by sets the primary criterion. Then by optionally selects a second criterion, and Finally by optionally selects a third. Each selector offers independent direction choices; None skips that optional criterion. For example, choose Dec: increasing in Sort by, Size: largest first in Then by, and RA: increasing in Finally by. Objects run from south to north; equal declinations are ordered by decreasing size, and objects with both equal declination and equal size are ordered by increasing RA. Each later criterion applies only when the preceding selected criteria tie. Numeric coordinates use their full saved precision, without rounding or declination bands. Missing values stay last at each level, in either direction. When all chosen criteria tie, constellation name and object identifier provide a consistent final order. Reset filters retains all three sort choices.

Sort by offers Constellation, Month: January–December, Month: December–January, Size: smallest first, Size: largest first, RA: increasing, RA: decreasing, Dec: increasing, and Dec: decreasing. Month sorting follows the numeric calendar order; unassigned months stay at the end in either direction. Size sorting uses the major apparent diameter and ranks objects across all constellations in a flat table, with unknown sizes last in either direction. RA and Dec sorting also use a flat table and compare numeric J2000 coordinates, with missing coordinates last. Increasing RA runs from 0 to 24 hours; increasing Dec runs from south to north. Constellation sorting orders the rows by constellation name and then object identifier. The Constellation column remains visible in every sort mode. Sorting preserves all highlighted rows, the current object and export checkboxes and does not modify the saved collection.

Constellation choices follow the Month filter: only constellations represented by objects in the selected list and planning month are offered. All months includes every represented constellation. Previous / current / next includes the constellations of all three planning months, including the December-January boundary. Unassigned month includes only objects without an assigned planning month. The choices use the collection's constellation-month mapping, including separate Serpens Caput and Cauda entries. Other filters do not narrow the Constellation menu.

Object type choices follow the selected list and all other active filters: Find, Month, Constellation, Target band and Imaging status. The current Object type choice is excluded when building this menu, so selecting Galaxy still leaves other matching types available to choose. Unspecified appears when matching objects have no saved classification. An empty matching set leaves only All object types.

Available selections are retained by value. A constellation or object type that becomes unavailable resets to its All option, and the table updates immediately. Month changes update Constellation first and then Object type, using the resulting constellation choice. The same rules apply when switching lists, editing object metadata or changing constellation-month assignments. If a month change removes the constellation used for an All filtered objects chart, its scope returns to Selected object. Reset filters restores all choices for the selected list. Hidden export checks and sorting are retained. Highlighting applies only to visible rows: filtering removes hidden rows from the highlighted selection while retaining highlights for matching rows. These filters do not perform catalog lookups or change saved object data.

The Month menu offers All months, individual months, Unassigned month and Previous / current / next. The latter shows objects assigned to the previous, current or next calendar month according to your computer's local date. For example, in October it includes September, October and November; in January it includes December, January and February. These are the planning months assigned to constellations in Configuration, not calculated visibility or imaging dates. Objects with an unassigned month are excluded. The month tooltip names the three included months, and the relative choice is recalculated whenever the table refreshes. It combines with the other filters and does not change sorting, export checks or saved collection data. Reset filters returns the month menu to All months.

Find searches identifiers, names, object types, target bands, filters, catalog information, comments and constellations. Results update while typing. Return or Enter in Find refreshes the results without opening New list or another dialog. If exactly one object remains visible after any filter, it becomes the current target automatically, so either preview tab loads it automatically without clicking its row, provided its coordinates are valid. This does not check it for export or add it to the highlighted selection. An empty result clears the target; with multiple results, choose a row unless the current target remains visible. Month and imaging-state filters narrow the display. Double-click a target to switch to Finder chart and display it automatically. Use the Edit object button to edit its details. The object-information section can be collapsed without shrinking the window; the table uses the freed space. Expanding it keeps the window dimensions when there is sufficient room, increasing only the minimum required size if necessary. Its heading shows an identical catalog identifier and display name only once, ignoring capitalization, spacing and the coordinate-marker suffix. A distinct display name remains beside the identifier. The close button offers to save only when collection content differs from its loaded or last-saved state. Filtering, sorting, export checks, previews, local preferences, collapsing sections and applying an unchanged editor do not count as collection edits. Reverting actual content to the baseline removes the prompt; bookkeeping timestamps and automatic classification snapshots alone do not trigger it. A failed save retains unsaved changes. New objects, changed memberships, imaging data, notes and constellation-month assignments still require saving.

3 Organize objects into lists

[hide]

A collection is the complete .sol file and owns every object independently of its lists. Each list is a named logical group inside that collection; List details changes the list name and description independently of the filename. An object may belong to no lists, one list or several lists. All objects displays every collection target once, including targets without a list membership. Repeated memberships do not create duplicate rows in this view.

Delete list deletes only the named grouping. Remove from list removes only the current object's membership in the selected list. Both keep every object in the collection, together with its catalog information, comments, filters, apparent size and imaging history. Objects whose final membership is removed remain available in All objects and can be added to another list later. A collection can be saved and reopened with no named lists.

To remove an object from the collection itself, select its row and use Delete object beside Add object and Edit object. This action always asks for confirmation, names the target and explains that it will be removed from every list together with its information. No is the default; declining or closing the question leaves the collection unchanged. Confirming removes only the current object, even when several rows are highlighted or checked. Save persists the deletion. Use Remove from list when you only want to change a grouping.

Check the objects to organize, then choose Add selected to list or Move selected to list. Checked objects take priority, including hidden checks across the collection. If nothing is checked, Ctrl-click or Shift-click to highlight rows and use those instead. The destination dialog reports the selected count.

Add selected to list retains every current membership and adds all selected objects to the destination. Move selected to list is available from named lists and All objects. Its dialog lets you choose a Source list from lists containing selected objects; the current named list is preselected when applicable. Only selected objects belonging to that source are moved. The dialog reports how many will move and how many selected objects outside the source will remain unchanged. Other memberships remain intact, and an emptied source list remains available.

In the destination dialog, choose an existing list or Create new list and enter its name. For Move, the chosen source is excluded from destinations. Add can use any list; objects already there are retained once. A new name must be nonempty and different from existing list names, ignoring capitalization and surrounding spaces. No new list is created until Add or Move succeeds. Cancel leaves the collection unchanged. Existing destination entries are retained without duplication; a move still removes their source membership.

New memberships retain the complete object information, including comments, filters, apparent dimensions, manual target band, imaging status and imaging date. Edits and imaging-state changes remain linked across memberships. Creating another membership is different from adding a duplicate catalog object: Add object still rejects a target already present in the collection and directs you to Add selected to list.

After applying, the manager displays the destination for review. Filters, all three sort choices and export checks are retained, and transferred objects that remain visible stay highlighted. Choose Save to persist the reorganized collection. Saving and reopening retains its objects, lists and shared identities; selected-object export still writes each target once, including selected targets without a list membership. Export selected beside the object actions opens the file chooser directly and writes the selected objects as one Stellarium list. It uses the same checked-first, highlighted-fallback selection rule. Cancel leaves files unchanged, and a partial export cannot overwrite the open collection file. Exporting does not change checks, memberships, imaging data or unsaved edits. The Collection Export command remains available for checked objects, one named list or Entire collection. Partial exports contain only objects in the chosen scope, including their saved metadata.

4 Save a collection path as a process instance

[hide]

The New Instance triangle in the lower-left corner saves the current collection path as a PixInsight process icon.

  1. Open a collection or create your lists and choose Save. The triangle is enabled when the collection has a filename.
  2. Save any changes you want to retain, then drag the New Instance triangle onto the PixInsight workspace.
  3. Save the process icon using PixInsight's standard process-icon or project commands if you want to keep it for another session.
  4. Run the process icon globally to reopen that collection in the manager.

The instance stores only the collection path. Objects, notes, imaging flags and unsaved changes are not embedded in the process icon; the manager reads the saved .sol file when the icon runs. The instance's path takes precedence over the most recently saved collection. You can create separate icons for different collection files.

If the file has moved, been renamed or cannot be read, the manager reports the problem instead of opening a different collection. Open the intended file and create a new instance to update the path. Save as changes the path used for newly created instances; existing process icons keep their saved paths.

5 Constellations and planning months

[hide]

Constellation names use their Unicode spelling, including Boötes, throughout the table, filters, configuration and charts. Imported constellation names may use the IAU code, the full name or the spelling Bootes.

For objects with coordinates, the constellation is calculated from the IAU boundary table of Roman (1987), after mean-equatorial precession from J2000 to B1875. This calculation works offline. For an imported object without coordinates, a recognized imported constellation is used until coordinates become available. An object without either is shown as unassigned and remains editable.

Click the Configuration gear button in the lower-right corner to open a separate settings window, then choose Constellation months to assign a planning month to each constellation. Configuration contains a Finder chart group for Sky coverage, Fit object size, Chart style, Label density and Close-up inset with its width; a DSS survey image group for Survey field and its separate Fit object size option; and the Stellarium outline-file chooser. Apply commits the proposed settings; Cancel discards them, including changes made in Constellation months. Chart settings and the local outline-file preference do not modify the collection. Applied constellation-month changes are collection edits. Initial assignments are provided for some constellations; others are unassigned until you choose a month. Serpens Caput and Serpens Cauda are separate planning entries. The mapping is saved with the collection and applies to every list in it.

Actual sky position determines the constellation and its planning month. An imported object whose constellation heading does not match its coordinates can appear in a different month. Imported notes remain available. These are personal planning categories; the script does not calculate local altitude, darkness, Moon distance, or visibility for a particular observing site.

6 Broadband and narrowband targets

[hide]

Target band is a separate column beside Object type. It shows Broadband, Narrowband or Unclassified. This is an imaging classification; it does not replace the catalog's object type. The cell tooltip explains the automatic evidence or identifies a manual choice. The object-information panel also shows the band and whether it is automatic or manual.

Automatic classification uses saved metadata locally, without catalog requests. Galaxies, star clusters, reflection nebulae, dark nebulae and integrated flux nebulae (IFN) always classify as Broadband in Automatic mode. Recognized galaxy types include starburst galaxies, galaxy groups, interacting galaxies and active galactic nuclei. Star clusters include open and globular clusters. SIMBAD type SBG is recognized as Starburst galaxy, both in new lookups and saved entries labelled Catalog object (SBG), without requiring another catalog lookup. Ha, OIII and SII are optional additions for these targets, so their presence does not change the band or erase the saved filter information. These exceptions use the object type; mentioning a nearby galaxy, star cluster, reflection nebula, dark nebula or IFN in the notes does not change the type of the target. For other targets, positive filter mentions in Filters, comments and catalog information take priority over object types. Ha, H-alpha, Hα, OIII, O III, SII and S II indicate narrowband; combinations such as SHO, HOO, HaRGB and LRGBHO are recognized. RGB, LRGB, explicit L/R/G/B channels and full-spectrum or broadband wording indicate broadband. For targets outside these Broadband categories, if both filter families occur anywhere in the considered metadata, narrowband wins. Explicitly negated mentions such as no OIII or without Ha are not treated as positive filter evidence.

Without recognized filter evidence, specific catalog types and descriptive metadata are used. Galaxies, reflection nebulae, star clusters, dark nebulae and integrated flux nebulae (IFN) indicate broadband. Emission nebulae, HII regions, planetary nebulae and supernova remnants (SNR) indicate narrowband. Common supported catalog abbreviations and German descriptions are recognized. Generic terms such as Nebula or Deep-sky object are insufficient and remain Unclassified. These rules are suggestions based on the available text, so review uncertain or conflicting metadata.

In Edit object, Target band offers Automatic, Broadband and Narrowband. The automatic result updates as you edit filters, comments or catalog information; hover over the adjacent result for the reason. Select Broadband or Narrowband to override the automatic result. Manual choices take priority over all automatic evidence, including these Broadband object-type rules and mixed filters, and survive Look up and Update catalogs. Choose Automatic to resume classification from the current metadata. Use the Target band filter's Unclassified choice to find entries that need a manual decision; it combines with the other view filters.

Apply keeps an edited choice in the collection; Save persists it. Save and all export scopes store the classification value and its automatic/manual mode in the object's _astroBucketList.targetBand metadata. Imports retain these fields. Automatic values are recalculated from current metadata when displayed and refreshed when saved, while manual values remain fixed until edited. Merely viewing or filtering a collection does not mark it modified.

7 Imaging state and notes

[hide]

Open Edit object and use I have imaged this object to record or clear imaging status. The Imaging status column shows the saved state and date independently of the export checkboxes. Edit object lets you enter or change the imaging date directly in YYYY-MM-DD format. The date field is always editable. Entering a date marks the object as imaged; clearing the date retains the imaged flag with an unknown date. Unchecking the imaging flag clears the date. Checking it with no date supplies today as an editable initial value. Invalid dates prevent Apply. The editor also stores an editable display name, imaging notes and Catalog information. A target recognized by its identifier or a matching primary catalog alias shares its imaging state across all lists containing it. Distinct members of a galaxy group remain separate targets.

Save persists all lists, imaging flags, dates, catalog information, comments, filter information, target-band classifications, apparent dimensions and month assignments inside the .sol file, in the namespaced _astroBucketList metadata fields. A changed window title has an asterisk, and closing offers Save, Discard or Cancel. There is no automatic overwrite of an imported source file. The script validates the new file before replacing the current one, keeps the previous primary file in the adjacent .bak file and removes temporary files after a successful save. The existing .bak is replaced only as part of a successful write. If replacement fails, it attempts to restore both the previous primary file and the previous backup; if restoration fails, the error identifies the retained recovery files. Backups with other names are left untouched. To recover an earlier version, copy the .bak file to a separate .sol filename and use Open. A single .bak retains only the immediately preceding save, not a full edit history.

8 Import and export

[hide]

Open, Save, Save as and Export share the same 32 MB limit on decoded JSON text. Before writing, the script validates the complete formatted output, including repeated object data in lists and collection storage. A larger result is rejected before changing the destination or its backup; your edits stay unsaved and the current collection path is retained. Export fewer objects or smaller lists to reduce the output. The limit is measured on decoded text, so the UTF-8 file on disk can be larger when names or comments contain non-ASCII characters.

The script accepts Stellarium observingLists JSON in .sol, .ol and .json files. A .sol file may contain one list or multiple lists. Export can write checked objects, the selected list or the complete collection. When objects are checked, Checked objects is selected initially in the export dialog. This creates a new single Stellarium list containing each checked target once, even when it belongs to several source lists. Identifiers, coordinates and saved object metadata, including imaging status and date, are retained. Objects hidden by the current filters remain part of the checked export. Save the result as a .sol file.

Full and selected-list exports preserve list UUIDs, memberships and unfamiliar Stellarium metadata fields. A checked-object or selected-list export cannot overwrite the currently open full collection. Opening another collection clears the temporary export selection.

Choose Import list in the Collection group to import objects from one saved list into a new named list or an existing destination. Select a .sol, .ol or .json file, then review the import dialog:

  1. Source list shows the lists in the selected file with their object counts. A single list is selected automatically. If the file contains multiple lists, you must choose which one to import, even if it defines a default list. Only the chosen list's objects are imported. Objects without a list is offered separately when the file contains ungrouped collection objects.
  2. Destination defaults to Create new list. New list name defaults to the selected source list's saved name and remains editable. Changing Source list updates an untouched suggested name, while retaining a name you customized. For ungrouped objects, the filename supplies the initial name.
  3. Enter a nonempty new name, or choose an existing destination from the menu. A new name must differ from existing names, ignoring capitalization and surrounding spaces. If the suggested name already exists, select that list as the destination or edit the name.
  4. Choose Import to merge the selected source objects into the collection and add their memberships to the destination. The summary reports the imported object count, new and matching collection objects, and the destination's total. Choose Save to retain the result.

Import list checks duplicates within the selected source and across the complete current collection, including objects in other lists or without a membership. Matching targets reuse one collection entry and appear once in the destination. Metadata follows the same conflict rules described below. Existing memberships remain intact. Repeating an import into the same destination adds only missing memberships and information; using a different new name creates another grouping for the same collection objects. Other source lists and source collection settings are excluded from this operation.

After Import list succeeds, Table displays the destination with view filters cleared so the imported objects can be seen. All three sort choices and checked objects are retained. The current collection path stays the same, and the source file is unchanged. Cancel, an invalid source choice, an invalid name or a file error creates no list and changes no collection data. An empty named source list can create an empty destination list.

Expand Collection and lists and choose Merge lists in the Collection group. Select one or more saved .sol, .ol or .json files. Their lists are merged into the current collection; its path and existing lists remain in place. Choose Save afterward to persist the combined collection. The source files are unchanged.

Matching objects are reconciled across the whole collection by stable object identity, catalog designation or a recognized primary catalog alias. A shared galaxy-group alias or identical coordinates alone does not merge differently named targets. Each object occurs once per list and can retain membership in several lists. Its reconciled details are shared across those memberships. Lists with a known UUID are merged; unfamiliar UUIDs add separate lists, even if the display names happen to match.

Current values take priority for conflicting coordinates, object type, display name, imaging date, apparent-size measurements and existing manual classifications. Missing values are filled from imported data. Distinct comment lines, catalog information, filter entries and catalog aliases are combined without repeating identical text. For conflicting single-value catalog facts, the current value is retained. Existing manual sizes and deliberately cleared manual catalog information remain intact. An incoming manual target-band choice is retained when there is no existing manual choice. Imaging status is combined: an incoming unmarked copy cannot erase an existing imaged flag.

The Merge lists summary reports added lists and objects, matching objects reconciled, and duplicate entries skipped. Reimporting the same data does not duplicate object memberships or accumulated text. Merge lists retains the active list, current object and export checks. All selected files are validated before committing the merge; if any file is invalid, the open collection is unchanged.

9 Load a saved collection in Stellarium

[hide]

Use the desktop version of Stellarium. The collection saved by Astro Bucket List is already an observing-list file; no conversion is needed.

  1. In Astro Bucket List, choose Save and note the .sol filename shown in the Collection group. Save includes every collection object and all named lists. To transfer only part of it, use Export and choose Selected list only or Checked objects instead.
  2. In Stellarium, press Alt+B to open Observing lists.
  3. Click the import button to open Import observing list. Browse to the saved .sol file, select it and choose Open. If necessary, choose the Stellarium Single Observing List (*.sol) file filter.
  4. Choose the imported list by name in Stellarium's observing-list dropdown. When the file contains several lists, all of them are imported and can be selected separately, even though the file filter calls .sol a single observing list.
  5. Double-click an object in the list to select it and move the sky view to its position. Named coordinate markers also work when the target's catalog identifier is absent from Stellarium's local catalog.

To transfer later changes, save the collection in Astro Bucket List and import it again. Stellarium can ask whether to replace a list with the same internal list identifier. Accept to update that Stellarium list, or decline to retain its current contents. Lists with different identifiers can coexist even when their names match. The saved collection retains its named lists. Objects without a membership are additionally exposed to Stellarium in an observing list named Objects without a list. This is an export view: reopening the collection in Astro Bucket List keeps those objects in All objects without creating a logical grouping for them. An empty collection without named lists exports an empty observing list with this name.

Native catalog objects keep their identifiers. Newly resolved objects default to named coordinate markers. Date, location, landscape and other existing Stellarium fields are retained on imported entries.

Keep the collection saved by Astro Bucket List as your master. Stellarium does not manage the script's imaging flags or notes and can discard these extra fields when it edits or re-exports a list. Reimport into the saved master to retain existing imaging flags; do not rely on Stellarium to archive the extra metadata.

See the Stellarium User Guide, Observing Lists (Bookmarks) for the observing-list window, and the Stellarium observing-list reference for its file structure.

10 Remember the last collection

[hide]

Open Configuration with the bottom gear and use the Startup checkbox Remember last opened or saved collection. It is off by default, including when a remembered filename already exists in PixInsight settings. With the checkbox off, normal launches start with an empty collection, and Open, Save and Save as do not record a startup filename.

Apply stores this independent preference in PixInsight settings alongside the filename. The flag uses AstroBucketList/rememberCollection and the path uses AstroBucketList/lastFile. They are local application preferences shared across collections, not collection metadata or process-instance parameters. Cancel leaves both preferences unchanged. Applying the toggle does not modify collection contents or mark the collection as changed.

Enabling it remembers the currently open file immediately; with a new unsaved collection, no path is remembered until Open or Save succeeds. While enabled, every successful Open, Save or Save as updates the path. Cancelled or failed operations retain the previously remembered path. Export, Import list and Merge lists do not replace it. Only the filename is remembered; unsaved edits are never saved automatically. The checkbox remains enabled across launches until you turn it off. Moving or renaming a file outside the script does not update its stored path. A missing or unreadable file is reported by its full path at startup; use Open to select the collection at its current location. A failed or cancelled Open leaves the remembered path intact. Adding or editing an object and then using Save keeps the same collection filename; the script does not add numbered suffixes.

Turning it off and applying clears the remembered path while leaving the current collection open. The next normal launch starts empty. A saved process instance still opens its explicit collection path, independent of this toggle. If remembering is enabled, a successfully opened process-instance collection also becomes the remembered file. The preference itself is never stored in the process icon.

[hide]

Choose Add object. In Add to list, select an optional destination or keep No list — collection only. Choose Save to persist it.

Cancel in the existing editor leaves stored metadata unchanged. Use Add selected to list for another membership. Imported memberships in multiple lists remain linked; repeatedly importing the same list does not create duplicate entries.

Catalog information is one editable field for the object description and catalog facts. Matching whole lines are shown once, including repeated object-type labels. Descriptive text imported with an object is included here. The object-information panel and Find use the same combined text. Comments remains separate for personal imaging notes. Choose Save to persist any consolidation prepared when opening a collection. List descriptions remain part of List details.

This is catalog information, not a generated prose account. The constellation and planning month are calculated locally. You can edit the display name, comments and Catalog information before applying. Edited catalog text is saved with the collection and retained by Look up and Update catalogs, including a deliberately empty text. Coordinates and apparent dimensions have separate editor fields. Update catalogs refreshes the object type. Editing the catalog prose does not change these structured values. 12 Apparent object size and catalog updates

[hide]

The Apparent size column shows the major diameter and, when available, the minor diameter, in arcminutes (the prime symbol). Unknown means no measured size is available. A missing minor diameter is left unspecified. The script does not treat Stellarium's field-of-view setting as an object measurement.

Look up in the object editor obtains available angular dimensions from SIMBAD. Update catalogs lets you refresh the selected object, objects with unknown sizes, or all objects in the chosen list. In All objects, the latter options cover the collection. These scopes use the list, regardless of the current search or month filter. Coordinates, object type, identifiers and catalog details are refreshed together. Only object identifiers are sent to SIMBAD. No size is invented when a catalog has none. Dimensions describe the catalog's measured extent and can vary with wavelength, surface-brightness limit and source.

In Edit object, leave Use catalog size checked to follow the catalog measurement. Uncheck it to enter a major and optional minor diameter in arcminutes. For arcseconds, divide by 60; for degrees, multiply by 60. The minor diameter must not exceed the major diameter. Leave both fields empty to explicitly mark the size unknown. Manual values, including an explicit unknown, survive catalog refreshes. Recheck Use catalog size to return to the catalog value. Size metadata is saved and exported with the collection, alongside the source information.

Catalog refresh preserves imaging flags, dates, comments, filters, edited catalog information, manual dimensions and existing list memberships. Linked memberships receive the same update. A failed lookup leaves that object unchanged. Stop a batch through the PixInsight process console; successful updates remain in memory. The completion message reports failures and missing catalog sizes. Choose Save to persist the updates.

13 Finder charts

[hide]

Select an object with coordinates in the Table tab, then switch to Finder chart or DSS survey image. Both previews are embedded in the main window. Finder chart provides a styled sky map with stars, constellation lines and catalog objects; DSS survey image provides the survey photograph. Both use the saved J2000 position and apparent dimensions. The default Finder preferences use 45-degree coverage with Fit object size unchecked. Unknown sizes start at 45 degrees. Enable Fit object size for coverage equal to six times the major diameter, within the chart limits. DSS defaults to Fit object size enabled, using 1.5 times the major diameter when known and the configured 30-arcminute fallback otherwise. Configuration preferences apply to all targets and are remembered between launches. Changing targets never resets manual widths, fitting choices, style, label density or close-up preferences. Uncheck fitting to choose a manual DSS width, except for a target larger than its 120-arcminute limit. Catalog lookup is optional.

To chart a constellation's current table results together, first choose a Constellation in Filter objects, then open the Finder chart tab and set Chart to All filtered objects. This option uses every row currently shown, after the selected observing list and all active filters: Find, Month, Constellation, Target band, Imaging status and Object type. Checked objects and highlighted rows do not restrict this chart. All objects includes each shared object once, even when it belongs to several lists.

The chart renders automatically. Each plotted target has an accent-colored ring and a number corresponding to the Objects in table order key below the map. The key retains the table's current sort order and complete object names. Nearby targets use offset numbers and leader lines. These explicit targets are always included, independently of enabled context catalogs, catalog magnitude limits and Label density. Optional catalog objects remain background context. Both Modern Editorial and Vintage Atlas support this chart, as do constellation borders, star labels, nebula contours and the other Chart details. Object details also adds types and known sizes to the key.

Coverage automatically fits the visible targets and their known major diameters, including the shorter vertical map dimension. The configured Sky coverage remains the minimum width (45 degrees by default); Fit object size does not prevent fitting the complete group. This mode can expand to 170 degrees when necessary. If a group cannot fit in one projection, the information block asks you to narrow the filters rather than omit objects. The map center is a calculated field center, not a target, so no center crosshair is drawn. Close-up inset is temporarily omitted for a group; the saved single-object preference is retained.

Objects without valid coordinates remain in the numbered key with coordinates missing and are not plotted; the information block reports their count, and its tooltip lists their names. Use Edit object or Update catalogs to locate them. If no rows remain, or none has coordinates, the old preview is cleared and the information block explains what is needed. Filter, list, sort and relevant object changes update the chart automatically when Finder is active, or the next time its tab is opened. Removing the Constellation filter, including with Reset filters, returns Chart to Selected object. The chart scope is a temporary view choice, not collection data or a saved preference. DSS survey image continues to show the individually selected object.

Use the bottom Open as image symbol to open the complete constellation chart and its object key in a native PixInsight image window for saving or printing through your normal image workflow. The chart is 1440 pixels wide; its height grows to include the full key. Zoom affects only the on-screen preview, not this output.

Both preview images support mouse-wheel zoom. Rotate the wheel forward to zoom in around the pointer and backward to zoom out. Drag with the left mouse button to pan a magnified image; double-click with the left button to fit the whole image again. The view is bounded from Fit to 1600 percent of the fitted size, with the current level shown in the information block. Zoom magnifies the loaded pixels; it does not change sky coverage, retrieve a new DSS field, rerun a catalog query or add resolution. Open as image still opens the complete original image. Each tab retains its own zoom and position while switching tabs, and resizing retains the viewed region where the image edges allow. Changing targets or preview settings resets the corresponding image to Fit. Zoom and pan do not modify collection data or saved configuration.

For DSS survey image, choose a square Survey field of 5 to 120 arcminutes in Configuration. Fit object size is beside Survey field in Configuration's DSS survey image group. The survey loads automatically when its tab is selected and after its field or fitting setting changes. If the object's major diameter exceeds 120 arcminutes, the request always uses 120 arcminutes, even when Fit object size is unchecked. The explanation appears in Configuration and in the consolidated information block above the preview. Configuration continues to show the preferred width; the temporary maximum does not replace it. Returning to a smaller target uses the preferred width or its size-based fit. The STScI survey image is centered on the object and displayed with a crosshair. This method requires internet access and is useful for identifying the appearance of a target and its immediate surroundings.

For the Finder chart, choose Sky coverage from 0.1 to 120 degrees in Configuration. The chart renders automatically for the current target and settings. The 1440 by 960 pixel landscape chart has a separate title band, a 1440 by 780 pixel sky map, and a coordinate and symbol key below the map. The width setting describes the horizontal field; the vertical field is smaller. Larger labels and star symbols remain distinct from the subdued grid and constellation lines. An accent-colored center crosshair identifies the selected target. The header shows the target name, apparent size, field width and orientation. The lower band provides J2000 coordinates, a symbol key and an angular scale measured at the field center. North is up and east is left. The sky map does not draw an image or camera FOV rectangle.

Chart settings are edited in the Configuration window opened by the bottom gear. The Startup group contains the independent Remember last opened or saved collection toggle. Its Finder chart group contains Sky coverage, Fit object size and Close-up inset controls, followed by compact Chart style and Label density choices aligned with the numeric fields. Its DSS survey image group contains Survey field and the DSS Fit object size checkbox. Changes remain proposed until Apply; Cancel discards them. The Finder tab contains the compact Chart scope choice, information and the preview. The bottom Chart details symbol opens a separate window, using a horizontal layout with annotations, the catalog checklist and its properties visible together. Apply commits the proposed details and redraws Finder automatically; Cancel retains the current details and loaded preview. An unchanged Apply reuses the preview. Preview rendering is paused while the details window is open. The symbol is enabled only on the Finder chart tab. The DSS tab contains the consolidated information block and survey image, with its settings in Configuration.

Chart style offers Modern Editorial and Vintage Atlas. Modern Editorial is the default, with a dark sky, clean sans-serif labels, blue-gray catalog markings and a cool accent crosshair. Vintage Atlas uses warm ivory paper, sepia star dots and catalog markings, serif labels, italic constellation names, fine double rules and a rust-colored target crosshair. Both use the same projection, coordinates, field width, catalog objects and label-density rules. The selected style is included when you use Open as image.

Applying a changed Chart style in Configuration updates only the Finder preview automatically. It retains sky coverage, Fit object size and catalog-detail choices. The choice remains active as you select other targets and is remembered locally for future launches. It does not modify the collection or DSS survey image. Each style has its own session cache entry.

Constellation borders in Chart details is enabled by default. It draws dashed region boundaries from PixInsight's bundled constellation-border data, using blue-gray strokes in Modern Editorial and sepia strokes in Vintage Atlas. Solid lines connect the constellation stars; a dashed sample in the footer identifies the borders. The boundaries use the same sky projection as the chart and work across the zero-hour RA seam and near the celestial poles. Turn the checkbox off for a simpler map. The active preview updates automatically. Changing this option retains the field width, object selection and DSS preview. Each border setting has its own cached chart. The option stays as chosen while selecting targets in this manager session; a new manager starts with borders enabled. Borders do not require internet access or change object counts.

Both preview tabs load automatically when selected. Changes to the current target or the active tab's settings are combined over a short delay, then use the latest values. Hidden tabs do not render or download; their updates wait until selected. Returning to an unchanged loaded preview reuses its bitmap without another request. Rendering is deferred while the manager is busy or a child dialog is active. Leaving a tab or closing the manager stops its pending timer. Finder uses local catalogs; new DSS fields require an internet connection. Loading can take a few seconds, particularly for a large survey image or detailed chart. Failed requests are reported in the information block without a popup or repeated automatic retry; choose Retry, change settings, or return to the tab to try again.

Each tab has one information block immediately above its preview, combining the target, J2000 coordinates, apparent size, loading/result status and any coverage limitation or error. The Finder block also reports whether outline data is available. A duplicate identifier and display name is shown once. The blank image area contains no additional instructions. The bottom Open as image symbol button becomes available when a preview tab is active and its image has loaded. It is disabled on Table and while the active preview has no loaded image.

Chart details groups the Catalogs checklist and its properties separately from the Annotations controls. Annotations contains Constellation borders, Nebula contours, Star names, Star magnitudes and Object details. The checkable All details symbol in the bottom bar selects or deselects all available annotation switches and catalog layers, including Messier. It is enabled only on the Finder chart tab. Its pressed state means all available details are selected; its tooltip describes whether clicking will enable or disable them. It skips missing catalogs and contours without a loaded outline file. It retains per-catalog label and magnitude properties and all Chart settings. Changing individual details updates the symbol's pressed state. Constellation borders, Messier and the installed NGC/IC catalog start enabled. Nebula contours starts enabled when a valid outline file is configured; the other catalogs and annotations start disabled. Selecting the first valid outline file also enables contours. You can switch any of these defaults off in Chart details; changing targets retains the choices for the session.

In Catalogs, check a row to include that catalog; select its name to edit the properties to the right of the checklist. The Contains column explains its purpose. All listed catalogs are local files supplied by PixInsight; missing files or classes are marked Unavailable and cannot be checked. The choices are:

  • Messier: bright deep-sky objects, including galaxies, nebulae and clusters.
  • NGC/IC: a larger general catalog of galaxies, nebulae and clusters.
  • Caldwell: a curated selection of additional deep-sky objects, overlapping other catalogs.
  • Collinder: open star clusters.
  • Green SNR: Galactic supernova remnants.
  • WISE H II: Galactic H II regions and candidates. Its sizes describe infrared apertures, which need not match the extent seen in an optical exposure.
  • Mandel–Wilson: large, diffuse integrated flux nebulae.

The installed data determine which choices are available. Hover over a catalog for its description and local file path; hover over the property summary for available data fields. These choices cover the bundled fixed-sky, deep-sky CSV catalogs. PixInsight also provides online VizieR catalogs, including Sharpless, Barnard, LBN/LDN, van den Bergh, PGC and others, with catalog-specific magnitude or passband controls. They are not queried by this offline Finder. The star background is separate and automatically prefers configured local Gaia data, falling back to bundled bright stars. Constellation geometry and the external Stellarium outline file are also separate layers.

Labels toggles text for the selected catalog while retaining its markers. Magnitude offers Automatic, Custom and No limit when the catalog supplies magnitudes. Automatic adapts to field width (up to magnitude 14 for Messier and NGC/IC, and 16 for Caldwell and Collinder); the summary shows the current threshold. Custom lets you enter the faintest magnitude from -5 to 25; larger values include fainter objects. No limit disables magnitude filtering. Unknown magnitudes are retained. Magnitude controls are disabled for Green SNR, WISE H II and Mandel–Wilson, which do not supply magnitudes. Catalog magnitude passbands can differ and are not interchangeable. These are drawing filters, not edits to the catalog data. Settings persist while choosing different targets during this manager session; catalog properties are not written to the collection or to PixInsight's catalog files. Automatic limits are recalculated for a close-up's own coverage; custom limits apply equally to overview and close-up.

Star density adapts independently to the field width. Markers remain visible for every included object after duplicate removal; labels use a spaced subset, preferring brighter targets, with overlap optimization. Label density and per-catalog Labels can reduce clutter without hiding markers. Dense catalogs, especially WISE H II, can make wide Galactic fields busy. The information block reports catalog objects after duplicate removal, excluding stars, so the number can exceed the text labels. Each combination of catalog selection and properties has its own session cache entry. Changes affect only the Finder preview, retaining collection data, imaging flags and DSS preview.

Star names prefers common names from the bundled named-star catalog and otherwise uses the catalog designation. Star magnitudes adds catalog brightness values, including unnamed stars when a local Gaia database provides them. The passband depends on the source catalog; Gaia and named-star magnitudes are not necessarily directly comparable. Label density offers Sparse, Normal and Detailed. It adjusts the number and spacing of star and object labels without changing the stars or object markers drawn. Brighter objects are preferred, with collision optimization; crowded fields do not show every label.

Object details adds short lines for catalog object type, angular size in arcminutes and magnitude, omitting unavailable values. Major and minor sizes are shown when the catalog supplies an axis ratio. Messier entries can obtain object types from their linked local NGC/IC records. Very large outlines retain compact name labels; the close-up information band provides the selected target's type and saved apparent size.

Nebula contours draws actual catalog polylines, separate from the circular or elliptical catalog object markers. It uses a local Stellarium or SkyChart outlines.dat file containing J2000 coordinates. The script detects common Stellarium installation locations. In the Configuration window opened by the bottom gear, Choose file sits directly beside the Outline file label and validates the selected Stellarium outline file. The status explicitly shows Loaded with the filename after successful validation, No outline file selected for an empty choice, File missing when a saved path is unavailable, or Not loaded for invalid data. Hover over the status to see the full path, validated outline count or error; the tooltips identify the Stellarium outline format. Loaded means the data is available; Nebula contours in Chart details controls whether it is drawn. A configured valid outline file enables contours at startup, and applying a first valid file enables them immediately. Replacing one loaded file with another retains an explicit off choice. Clear file stages an empty selection. Apply deselects the file, turns contours off and updates the Finder preview; Cancel retains the current selection. The file on disk and the DSS preview remain intact. The chosen path, including a deliberately cleared choice, is remembered locally across launches and is not stored in the collection. Automatic discovery does not replace an explicitly cleared choice. Without a valid loaded file the Nebula contours checkbox is disabled. Only objects represented in that file can have contours, and a field may contain none. The information block reports how many contours intersect the overview. No contour file is downloaded or included in the script package. Edited contour-file contents invalidate the cached chart.

Close-up inset in Configuration's Finder chart group adds a separately projected square map beside the overview, keeping the whole overview visible. Its preferred Coverage is in degrees, defaults to 2 degrees and applies to all targets. If this width is at least as large as an object's overview, that chart uses half the overview width, with a minimum of 0.1 degrees, while the preference remains unchanged. At the minimum 0.1-degree overview the inset is temporarily hidden. A wider overview restores it automatically when the saved inset preference is enabled. The close-up uses the same style, catalogs and detail choices, with star density adapted to its narrower field. Both maps mark the same target center. With the inset enabled the chart is 2080 by 960 pixels, including the unchanged 1440-pixel overview and a separate 600 by 600 pixel close-up map. Open as image includes the complete chart with all selected details.

The Configuration window displays the preferred preview widths. Sky coverage affects Finder chart; Survey field affects DSS survey image. You can configure both previews even without selecting a target. When Fit object size is checked, its width control is read-only and shows the fallback width used for unknown sizes. Uncheck fitting to edit that width. A known size produces a fitted field for each target without replacing the stored width; an unknown size does not turn fitting off for later targets. The DSS maximum and close-up bounds likewise constrain only the displayed chart. Apply saves these preferences locally and updates the active affected preview; a hidden preview updates when selected. Cancel retains both active and saved preferences. These settings are independent of collection data and process-instance paths. Constellation months remain collection data, and the outline-file path remains a local preference.

Each preview tab keeps its own coverage setting and loaded image. Switching tabs retains both previews. Selecting a different object, changing its position or size, or editing preview settings clears the affected preview so a stale image is not shown for a new target. Selecting the relevant tab automatically updates a missing or stale preview using its current settings. A target without coordinates cannot start a preview request. The chart source appears in the same information block as the other preview messages. Configured full Gaia DR3, EDR3 or DR2 XPSD catalogs are preferred through the Gaia process's BestAvailable selection. If those are unavailable, a configured Gaia DR3/SP database is used. Star positions are propagated to J2000 for consistency with the list coordinates. Constellation, Messier and NGC/IC annotations also use files bundled with PixInsight. Sky charts do not require a network connection and do not change the Gaia configuration.
