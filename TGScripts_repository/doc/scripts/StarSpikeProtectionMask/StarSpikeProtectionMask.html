1 Description

[hide]

Star Spike Protection Mask 1.6 creates a full-resolution Float32 grayscale mask using native CIE Y luminance. Grayscale sources are used directly. Bright cores and spike ridges receive strong protection; faint wings taper with their measured signal. The source remains unchanged.

Black protects. White allows processing. Leave Invert Mask OFF.

The script targets PixInsight 1.9.5 with V8 and stretched stars-only images with approximately perpendicular spikes. STF does not affect measurements.

2 Parameters

[hide]

2.1 Minimum bright-core area (px)

Default 100. Main lower selection cutoff: connected pixels above the core luminance threshold after slight smoothing. Increase for fewer, larger stars. This is a size-based brightness proxy, not a calibrated magnitude.

2.2 Core luminance threshold

Default 0.60. Normalized native luminance defining the detected core. Reduce for darker data. Selection now uses CIE Y rather than the brightest RGB channel, so counts and suitable thresholds can differ from previous versions.

2.3 Required spike arms (0 = any)

Default 2; range 0 to 4. Zero includes qualifying round stars. Two accommodates many asymmetric or edge-clipped patterns; higher values require more evidence.

2.4 Minimum luminance contrast

Default 0.025. Minimum signal above background used for spike evidence, core wings and transverse profiles. Raise to tighten masks and reject faint structures. Lower for faint spikes. Local noise estimates can raise the effective threshold. Strongly colored stars may be dimmer in luminance than under the old maximum-RGB detector.

2.5 Measure spike angle automatically

Default enabled. Estimates shared orientation from large candidates, then refines individual angles. Disable to use the manual angle.

2.6 Spike-axis angle (degrees)

Default 0. Manual angle clockwise from horizontal in image coordinates; angles are equivalent modulo 90 degrees. Used only when automatic measurement is disabled.

2.7 Maximum spike length (px)

Default 600. Upper measurement limit per arm. Each arm is independent: there is no opposite-arm extension or added tip margin. Increase if the console reports the limit being reached.

2.8 Core radius (%)

Default 100; range 10 to 200. Scales the luminance-shaped central profile. Try 60 for tighter cores. Remote spike geometry is unchanged. This is not a solid disk radius; protection within the footprint follows actual luminance. Version 1.5 changes the profile, so 100 percent does not reproduce version 1.4 masks.

2.9 Grow protected area (px)

Default 0; range 0 to 12 whole pixels. Expands all protected cores and spikes by a circular morphological radius. Try 2 or 3 pixels, with blur initially at zero. Gray protection levels are retained. Growth does not change which stars were selected or the image dimensions, and is applied before optional Gaussian blur. Nearby regions can merge. A radius of 2 adds approximately 2 pixels on each side of a long narrow spike. Zero is an exact bypass.

2.10 Whole-mask blur sigma (0 = off)

Default 0; range 0 to 25. Zero disables Gaussian smoothing. Profiles already provide natural soft edges. If needed, try 2 pixels for additional smoothing of the finished mask. Blur spreads transitions and can weaken protection of narrow spikes.

2.11 Offer to save the result as XISF

Default enabled. Show Save after interactive creation. Cancelling leaves the mask open. Saving over the source is rejected. View-target execution leaves the mask open without a save dialog.

3 Usage

[hide]

Open the stars image, run Script > TG Scripts > StarSpikeProtectionMask, select the source, set the lower core-area limit and click the preview magnifier. Inspect the Mask preview at 1:1, using zoom and pan. Source comparison shows the original image without STF. Click the green checkmark to create the full-precision mask and optionally save XISF. Apply it to the matching target with mask inversion disabled.

4 Installation and symbols

[hide]

Extract the archive and keep its TG Scripts folder intact, including doc/ and rsc/. Register this folder with Script > Feature Scripts > Add. The script identifier is StarSpikeProtectionMask. Help opens this bundled PIDoc manual.

The bottom toolbar provides a triangle for New instance, a preview magnifier, a green Create checkmark, a red Close cross and a Help icon. Tooltips name each action. Drag the triangle to save settings on the workspace. Double-click the resulting icon and use the Script panel's blue Apply Global circle to reopen the dialog. Save process icons or the project to retain them across sessions. Drag an instance onto a main image to create its mask without a save dialog. Preview targets are rejected.

5 Simplified controls and morphological growth

[hide]

Settings contains the source, minimum core area, luminance contrast, core radius, growth, blur and save preference. The separate Detection tab contains core threshold, required arms, automatic/manual angle and maximum search length. The extra minimum-peak control was removed: disabling it on RGB_clone_stars.xisf left the same 132 selected stars.

Minimum core area changes which stars qualify; it does not resize the mask for a retained star. Core radius resizes only the central profile. Growth expands the complete protection. Luminance contrast affects faint profile support and can change selection. Maximum length only caps the search, so increasing it has no effect when all detected spikes end earlier. Manual angle applies only when automatic measurement is off.

Since black protects, growth is native grayscale Erosion of the finished mask, equivalent to dilation of inverse protection. One full-strength pass uses a disk with diameter 2r+1, containing grid points whose squared distance from the center is at most r squared. The maximum radius 12 corresponds to PixInsight's maximum 25-pixel structure size. Zero skips the process entirely. No binary threshold or rescaling is applied. Growth is clipped at image boundaries. Optional Gaussian blur follows growth.

Inspect at 1:1 with zero blur, starting with 2 pixels of growth. Save the chosen settings with the triangle instance button. The same growth is used in preview, interactive creation and view-target execution.

6 Algorithm and size improvements

[hide]

Native Image.getLuminance computes CIE Y with the source RGB working space. Full-image extraction preserves selections and ignores STF. Bright connected cores establish centers and selection. Robust ray measurements establish orientation and independent arm lengths.

A radial median profile bounds each core while local luminance supplies its shape. For every detected arm, transverse profiles are sampled along its length. Local background, the radial halo profile and a robust noise floor are subtracted. Only the transverse component touching the central ridge is retained. Detached cross-axis neighbors are rejected. Strong signal maps to black protection and faint wings to gray. Missing arms receive no profile.

The old fixed-width bands, artificial arm extensions, broad solid disks, tip margins and geometric feathering have been removed. Core and spike weights are combined, inverted and optionally blurred. No histogram normalization is applied.

7 Preview and instance migration

[hide]

Preview uses the same complete calculation as Create, including blur, then displays an 8-bit bitmap. The output remains Float32. Preview includes morphological growth and subsequent blur. No preview image window is retained. Changed settings clear stale previews. Refresh explicitly to see the new mask and star count. Create rereads the source.

Schema 4 stores twelve parameters, including growth. Older instances default to zero growth. The redundant minimum-peak cutoff is ignored, which can admit additional stars on some images. Older icons retain supported settings and migrate legacy enable flags, but always run the new luminance algorithm. Obsolete padding, edge softness and halo-floor settings are ignored. Review the preview and save a new icon. A closed or renamed source must be selected again.

8 Limitations and validation

[hide]

Profiles assume straight, approximately perpendicular spikes. The transverse search extends 12 to 32 pixels on either side; wider, curved or severely crowded spikes can need manual correction. Stars lying directly on a spike can contaminate its profile. Linear data requires adjusted luminance thresholds or a stretched detection copy. Source and mask must receive identical geometric transformations.

Native tests cover native luminance and preserved ROI, asymmetric arm lengths and widths, missing arms, detached neighbors, brightness tapering, core-radius independence, preview equality, whole-mask blur, XISF round trip and saved parameters. Tested on RGB_clone_stars.xisf at 6004 by 3908 pixels: 132 stars selected with defaults, saved as Float32 grayscale XISF and reopened with exact sample equality. The previous geometric version selected 869 with its defaults. These counts differ because CIE Y replaces maximum-RGB intensity; the mask-size comparison reflects both selection and profile changes.

Version 1.6 requires a new code signature. An older xsgn must not accompany this edited script. Source comments and the companion developer notes describe the implementation and tests.
